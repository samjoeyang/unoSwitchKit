## 商业化授权方案（设计稿，未改代码）

- 产出 `docs/商业化授权方案.md`：试用 N 天 + 激活码 + 设备数限制的完整设计。
- 核心结论：采用「在线激活 + 离线 Ed25519 签名令牌兜底」，拒绝纯离线码（无法真限制设备数）与 Keygen.sh（Std $299/mo 对小工具不划算）。
- 关键技术点：
  - 试用期三处冗余（AppConfig / Keychain / UserDefaults）+ HMAC + 时钟回拨检测；残余风险「删三处重装可重置」建议接受。
  - machine_id = base32(sha256("switchkit/v1|" + IOPlatformUUID + hw.model))[0..16]，不用 MAC。
  - 令牌含 mid + exp(30d)，本地验签 → 服务端挂/断网不影响已激活用户；服务端只管计数与签发。
  - 门控在 Rust 侧（commands.rs 加 `require_write`），前端只做 UX；只读命令不加门。
  - 计划新增 `src-tauri/src/license/{mod,machine,trial,token,api,guard}.rs` + 4 个新命令。
- 支付渠道调研（2026-10，二手信息需自验）：Creem 有实测可跑通；Paddle 说法冲突；Lemon Squeezy 2026 起停止接受大陆主体新申请；Gumroad 支持但有 license 无设备计数。
- 提醒事项：现有 README 声明「默认不联网、不上报」需随激活功能修订；macOS 代码签名+公证是商业化前置项，当前 tauri.conf.json 未配置。
- 待用户决策：是否上 App Store（是则须走 StoreKit IAP，本方案作废）、买断/订阅、设备上限、硬锁 vs 软锁、销售主体。
