# 构建与运行指南（SwitchKit）

> 适用对象：从零搭建 / CI / 实体机联调。
> 本仓库已在 macOS 12.7.6 + Rust 1.99 下通过 `cargo check`（后端）与 `npm run build`（前端）验证。

## 1. 前置依赖

| 依赖 | 版本 | 安装 |
|---|---|---|
| Node.js | ≥ 18 | `brew install node` |
| Rust (stable) | ≥ 1.77 | `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs \| sh` |
| Xcode Command Line Tools | — | `xcode-select --install` |
| Tauri CLI | v2 | 随 `npm install` 进入 `devDependencies`，用 `npm run tauri` 调用 |

### Rust 双架构 target（universal 包用）

```bash
source "$HOME/.cargo/env"
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

### Swift 守护进程（sidecar）编译

蓝牙设备（IOBluetooth）由 Swift 守护承载，`tauri dev/build` 不会自动编译它，需先手动构建（Rust 启动时按 `src-tauri/binaries/switchkit-daemon-<arch>-apple-darwin` 自动拉起）：

```bash
cd src-tauri/swift
swiftc -O -framework AppKit -framework ApplicationServices -framework Network -framework IOBluetooth \
  main.swift bridge.swift bluetooth.swift \
  -o ../binaries/switchkit-daemon-$(uname -m)-apple-darwin
```

> 排查守护问题时看 `~/Library/Logs/switchkit-daemon.log`。

> 发布 universal 包时分别用 `-target x86_64-apple-darwin` 与 `-target arm64-apple-darwin` 各编译一次，再 `lipo -create` 合并。

## 2. 本地开发

```bash
npm install
npm run tauri dev      # 启动前端(dev server) + 编译/运行 Rust，支持热更新
```

> `tauri dev` 会先 `npm run dev`（Vite @ :1420）再启动 Rust 主进程。
> 首次编译 Tauri 依赖较多（数分钟），请耐心等待。

## 3. 生产构建

```bash
./scripts/build-release.sh              # Apple Silicon + Intel 通用包（默认）
./scripts/build-release.sh --current    # 仅当前架构（本地验证，勿用于分发）
```

> 默认走 universal：脚本分别在 `--target arm64-apple-macosx12.7.6` 与
> `--target x86_64-apple-macosx12.7.6` 下交叉编译 Swift 守护进程，`lipo` 合并；
> Rust 侧由 `tauri build --target universal-apple-darwin` 产出双架构主程序。
> 构建结束后脚本会硬校验两个可执行文件都含 `arm64` + `x86_64`，缺失直接失败。
> **漏掉 arm64 切片的包在 Apple Silicon 上会要求安装 Rosetta 2。**

脚本自动完成：Swift 守护编译（含 ad-hoc 签名）→ 签名身份检测 → `tauri build`（守护进程经 `externalBin` 打进 `Contents/MacOS/switchkit-daemon`）→ 产物签名收尾与校验。

不用脚本时的手动等价流程：

```bash
npm run tauri build                         # 当前架构
npm run tauri build -- --target universal-apple-darwin   # Apple Silicon + Intel 通用包
```

产物位于 `src-tauri/target/(debug|release)/` 或 `src-tauri/target/universal-apple-darwin/release/`。

## 3.1 分发签名策略（既定：长期 ad-hoc，不申请 Developer ID / 不公证）

| 场景 | 签名 | 用户首次打开体验 |
|---|---|---|
| **当前分发（本脚本默认，无证书）** | ad-hoc（`codesign -s -`） | 弹「未验证开发者」；macOS 15+ 只能走 系统设置 → 隐私与安全性 → 仍要打开（先点「完成」关掉首次弹窗，再点「仍要打开」，需触控 ID / 管理员密码，按钮约 1 小时内有效） |
| （本项目不采用） | Developer ID Application + 公证 | 双击直接打开 |

**项目决策**：不申请 Developer ID、不做 Apple 公证，接受「每个新包手动放行 + 每次换包重新授权 TCC 权限」。因此不要把「以后补公证就好了」写进实施计划；`scripts/setup-selfsign.sh` 的固定自签证书仅作可选工具保留，**不接入 CI**。§6 的公证流程仅作背景参考，不是本项目发布链的一环。

ad-hoc 包注意：
- macOS 15 Sequoia 起已移除「右键 → 打开」绕过，旧文档与脚本注释中的说法已过时。受管设备（MDM）可完全禁止用户放行，此时 App 无法启动。
- 每个新下载包、每次 OTA 更新后都要重做一次放行；若提示「已损坏，无法打开」，可 `xattr -dr com.apple.quarantine /Applications/SwitchKit.app`。
- **TCC 隐私授权每次换包都会静默失效**：新 cdhash 被 TCC 当作新 App，系统设置里的开关仍显示「开」且通常不重新弹窗。恢复流程为「退出 App → `tccutil reset All com.switchkit.app` → 重开 App → 逐项触发功能重新弹窗」，个别系统级服务需 `sudo` 或重启 macOS；详见 §5 与 README「每次更新后需重新授权」。App 内已提供签名变化检测、权限自检与重置引导。
- 守护进程随包签名；Apple Silicon 上无签名二进制会被系统直接杀掉。
- Homebrew 官方 cask 自 2026-09 起要求通过 Gatekeeper 检查，本包无法进入官方 cask；分发走 GitHub Release 与官网直链。

**Release 说明固定段落**（已由 `.github/workflows/build.yml` 的「提取变更详情」步骤自动写入 Release 正文与 OTA manifest，无需手动复制）：

> 本版本为 ad-hoc 签名、未经 Apple 公证。下载后请在「系统设置 → 隐私与安全性」点「仍要打开」。**每次更新都会使系统隐私授权失效**：完全退出 SwitchKit，在终端执行 `tccutil reset All com.switchkit.app`，重新打开 App 后逐项触发功能并允许授权弹窗。App 面板顶部会显示重新授权提示。

## 4. 分发前准备（NFR-2 / 设计文档 §8）

- **Apple 公证（notarize）**：本项目**不做**，见 §3.1 的既定决策。未公证的包会被 Gatekeeper 拦截，需用户手动放行；§6 仅作背景参考。
- **在线更新（OTA）**：已接入 `tauri-plugin-updater`（Tauri 自带实现，非 Sparkle），配置方法见 §6.6。minisign 只验包完整性，不提供 macOS 代码签名身份；落地的新 `.app` 仍是 ad-hoc，可能被 Gatekeeper 拦，且**必然触发一次 TCC 授权失效**，发版说明须附 §3.1 的固定段落。
- **App Store**：暂不走 App Store（沙盒会限制系统命令），官网/直链分发。

## 5. 权限说明（运行时）

| 操作 | 是否需 root | 通道 |
|---|---|---|
| 深色模式 / 隐藏桌面 / 阻止睡眠 / 清空废纸篓 | 否 | 直接 shell |
| 释放内存（`purge`） | 是 | `osascript … with administrator privileges` 弹系统密码框 |
| 刷新 DNS | 是 | 同上 |
| 清理用户缓存 | 否（用户级） | 仅白名单目录 |
| 蓝牙开关 | 否 | Swift sidecar 调系统框架 `IOBluetooth` |

> 凭据不落盘、不进日志、不硬编码。`SMJobBless` privileged helper（设计文档 §4.5）在本项目的 ad-hoc 签名下不可行：Apple 要求 app 与 helper 均由 Developer ID 签名，且 `SMPrivilegedExecutables` / `SMAuthorizedClients` 写死 `anchor apple generic …` 的 code signing requirement，自签证书也过不了；该 API 自 macOS 13 起已弃用。因此 `purge` / `flush_dns` 长期停留在每次输密码，若未来要改应评估 `SMAppService`。

### 5.1 TCC 隐私权限与换包失效

上表只列 root 通道，以下操作还依赖 TCC 隐私授权：自动化（Finder / System Events）、完全磁盘访问、文件和文件夹、蓝牙，以及后续若加入的屏幕录制 / 麦克风 / 辅助功能。ad-hoc 签名无稳定 designated requirement，TCC 按 cdhash 记录授权；**每次重新构建、下载新包或 OTA 更新 → 新 cdhash → 全部授权静默失效**，且系统设置开关仍显示「开」、不重新弹窗。

恢复命令（Apple 官方 `tccutil` 语法，service 名大小写敏感）：

```bash
tccutil reset All com.switchkit.app                 # 重置本 App 的所有隐私权限
tccutil reset AppleEvents com.switchkit.app        # 只重置自动化
tccutil reset ScreenCapture com.switchkit.app      # 只重置屏幕录制
```

不带 `sudo` 只作用于当前账户。流程：退出 App → 重置 → 重开 App → 逐项触发对应功能使其重新弹窗 → 允许。个别系统级服务（ScreenCapture / Accessibility / SystemPolicyAllFiles / ListenEvent / PostEvent）可能需 `sudo` 或完全重启 macOS。App 内的「权限自检」通过比对当前 `codesign` CDHash 与上次记录值来判断是否换包，并在面板顶部提示；预检结果可能滞后于刚完成的授权，必要时重启 App 再查。

## 6. 公证分发（本项目不采用，仅作背景参考）

### 6.1 前提

| 项目 | 说明 |
|---|---|
| Apple Developer Program | ¥688/年 |
| Developer ID Application 证书 | developer.apple.com 手动创建（CSR 流程），只有账户持有人可建 |
| App 专用密码 | appleid.apple.com → 登录和安全 → App 专用密码 |

### 6.2 存储公证凭证（一次性）

```bash
xcrun notarytool store-credentials "switchkit-notary" \
  --apple-id "你的AppleID" --team-id "TEAMID"
# 按提示输入 App 专用密码，凭证进钥匙串，之后不落明文
```

### 6.3 Tauri 配置与构建

`tauri.conf.json` 无需加公证字段，环境变量齐全即自动公证：

```bash
export APPLE_SIGNING_IDENTITY="Developer ID Application: 你的名字 (TEAMID)"
export APPLE_CERTIFICATE_PASSWORD=""        # 证书导入钥匙串时如设过密码才需要
export APPLE_ID="你的AppleID"
export APPLE_PASSWORD="App专用密码"
export APPLE_TEAM_ID="TEAMID"
./scripts/build-release.sh
```

Tauri 自动完成：hardened runtime 签名（含 `externalBin` 守护进程）→ `notarytool submit --wait` → `stapler staple`。

### 6.4 验证

```bash
APP=src-tauri/target/*/release/bundle/macos/SwitchKit.app
spctl -a -vv "$APP"                # 期望: accepted source=Notarized Developer ID
xcrun stapler validate "$APP"
codesign -dv "$APP/Contents/MacOS/switchkit-daemon"   # 守护进程必须已签名，否则公证被拒
```

### 6.5 手动公证（不依赖 Tauri 自动流程）

```bash
ditto -c -k --keepCompressed "$APP" SwitchKit.zip
xcrun notarytool submit SwitchKit.zip --keychain-profile "switchkit-notary" --wait
xcrun stapler staple "$APP"
```

### 6.6 在线更新（OTA）配置

已接入 `tauri-plugin-updater`（Tauri 自带实现，非 Sparkle）。**当前 CI 已自动接入 OTA**：`.github/workflows/build.yml` 在配置了 `TAURI_SIGNING_PRIVATE_KEY` secret 时，把 `SWITCHKIT_UPDATE_ENDPOINTS` 指向 GitHub Release 的 `releases/latest/download/latest.json`，构建期注入 `plugins.updater.endpoints` 与 `createUpdaterArtifacts`（构建后还原、不入库），并生成 `latest.json` 随 Release 发布。只有未配置该 secret 时才显示「更新服务尚未配置」。

> `build.yml` 的「提取变更详情」步骤会把 §3.1 的「安装与更新后必读」（含 `tccutil reset All com.switchkit.app`）固定写入每次 Release 正文与 OTA manifest，无需手动附。

以下为端点 / 密钥的手动配置参考（自建更新服务器时使用）：

1. **签名密钥**（已生成，公钥已写入 `tauri.conf.json` `plugins.updater.pubkey`，私钥在 `~/.switchkit-updater-secret.key`，切勿入库）：
   ```bash
   npm run tauri signer generate --ci -w "$HOME/.switchkit-updater-secret.key"
   ```
2. **更新服务器**：提供一个 manifest（如 `https://<host>/update/{{target}}/{{arch}}/{{current_version}}` 形式的静态 `update.json`），并对每个发布产物 zip 用 `TAURI_SIGNING_PRIVATE_KEY` 签名。
3. **构建时导出端点**：脚本会自动把端点写入 `tauri.conf.json` 的 `plugins.updater.endpoints`（构建后还原，不入库），同时 `option_env!` 把 `enabled` 固化进二进制：
   ```bash
   export SWITCHKIT_UPDATE_ENDPOINTS="https://example.com/update/{{target}}/{{arch}}/{{current_version}}"
   ./scripts/build-release.sh --universal
   ```
4. 构建出的包即具备 OTA 能力；用户在面板点「检查更新」即可下载安装并重启。

> 注意：minisign 只验更新包完整性，落地的新 `.app` 仍是 ad-hoc 签名，可能被 Gatekeeper 拦截（需用户重新走「仍要打开」），**且必然使所有 TCC 隐私授权失效**。这是 §3.1 既定决策下可接受的代价：App 重启后会因检测到签名哈希变化而在面板顶部弹出重新授权引导。发版说明必须附 §3.1 的固定段落。

## 7. 常见问题

- **面板不显示 / 黑屏**：确认 `tauri.conf.json` 中 `bundle.macOS.activationPolicy = "accessory"`，且窗口 `transparent: true` 时背景为透明（毛玻璃由 CSS 实现，非系统 vibrancy）。
- **`cargo check` 报 frontendDist 缺失**：先 `npm run build` 生成 `dist/`，或保留占位 `dist/index.html`。
- **蓝牙开关无效**：确认 Swift sidecar 已随包启动（面板底部「原生守护」状态点应点亮）；蓝牙走系统 `IOBluetooth` 框架，无需第三方工具。
- **最低系统版本**：`tauri.conf.json` 的 `bundle.macOS.minimumSystemVersion`（当前 `12.7.6`）必须与 Swift 切片部署目标一致。只改一边会出现「Info.plist 承诺版本与实际二进制部署目标错配」的错配，老系统装上即崩。改版本时同步改 `scripts/build-release.sh` 里的 `MACOS_MIN`、`.github/workflows/build.yml` 的 `MACOSX_DEPLOYMENT_TARGET`、README / PRD / 设计文档 / 官网。Tauri 打包器源码（`crates/tauri-bundler/src/bundle/macos/app.rs`）是把该字符串**原样**写进 `LSMinimumSystemVersion`，不做版本解析或截断，所以三段版本号 `12.7.6` 与脚本的字符串硬校验可以直接对齐；本机实测 `swiftc -target x86_64-apple-macosx12.7.6` 产物 `LC_BUILD_VERSION.minos = 12.7.6`。注意精度到补丁号会排除 macOS 12.0–12.7.5。
