# 登录与功能分层方案

> 状态：已实现（v0.4.15 起）。认证服务：`https://auth.zhenzhidaole.com`（UNOAuth，OAuth 2.1 / OIDC）。

## 1. 认证服务事实（实测，2026-11-19）

来源：`https://auth.zhenzhidaole.com/.well-known/openid-configuration` 与端点实测响应。

| 项 | 值 |
|---|---|
| issuer | `https://auth.zhenzhidaole.com/api/auth` |
| authorize | `https://auth.zhenzhidaole.com/api/auth/oauth2/authorize` |
| token | `https://auth.zhenzhidaole.com/api/auth/oauth2/token` |
| userinfo | `https://auth.zhenzhidaole.com/api/auth/oauth2/userinfo` |
| revoke | `https://auth.zhenzhidaole.com/api/auth/oauth2/revoke` |
| grant | `authorization_code` / `refresh_token`；**不支持 password** |
| PKCE | S256 |
| id_token 签名 | EdDSA |
| 动态注册 | **禁用**（`POST /api/auth/oauth2/register` → `403 Client registration is disabled`） |
| 本应用 client | `GCiqJXOkplapPOBUnUJcDBKCjzjITHlJ`，**public client（无 secret）** |
| 回调 URI | `unoswitchkit://callback/`（服务端严格校验，错一个字符即 `invalid_redirect`） |

token 端点实测：裸 `client_id` + PKCE 正常进入 code 校验；带 Basic 头反而 `invalid_client`。**不要加 client_secret**。

## 2. 登录流程（RFC 8252 桌面最佳实践）

1. 用户在「设置 → 账号」点「登录」。
2. Rust `auth_login` 生成 PKCE verifier + state，注册一次性回调通道。
3. 系统浏览器（`/usr/bin/open`）打开 authorize URL。
4. 用户在网页登录，服务重定向 `unoswitchkit://callback/?code=&state=`。
5. `tauri-plugin-deep-link` 收到 URL → `auth::handle_callback_url` 唤醒等待中的登录。
6. 校验 state → POST token 端点（body 带 client_id + code_verifier）换 access/refresh token。
7. GET userinfo 取 email/name → 会话落盘 `~/Library/Application Support/com.switchkit.app/session.json`（权限 600）。
8. 面板登录态更新，锁定功能解锁。

登出：服务端 revoke refresh_token + 删除本地 session。

## 3. 功能分层

### 免费（未登录可用）
- 快捷开关：外观、隐藏桌面、阻止睡眠、隐藏 Dock、显示隐藏文件、屏幕清洁、台前调度、锁定屏幕、清剪贴板、屏保、截屏录屏、清空废纸篓
- 资源监控：CPU / 内存 / 网络实时展示（只读）
- 清理扫描：扫描、空间分析、占用排行、大文件列表（只读查看；**不执行删除**）
- 设置：开关排序、开机自启、检查更新、权限自检

### 登录层（登录后解锁）
| 功能 | 后端门控点 |
|---|---|
| 释放内存 | `release_memory` |
| 刷新 DNS | `flush_dns` |
| 执行清理 / 大文件删除 | `clean_selected` / `trash_path` |
| 回收站恢复 / 清空 | `restore_trash_item` / `empty_switchkit_trash` |
| 定时自动清理 | `run_auto_clean_if_due` |
| 蓝牙连接 / 断开 | `bt_connect` / `bt_disconnect` |
| 模型余额查询 | `get_balances`（未登录返回空） |
| 余额 Key / 代理 / 自动清理设置 | `save_settings` 字段级门控 |
| 全局快捷键自定义 | `set_shortcut_bindings` |

前端锁标（`🔒`）+ `gateFrontend()` 只是 UX；**Rust 命令层的 `require_login()` 是唯一权威**。

## 4. 会话与安全边界

- token 存本地文件、权限 600，与同目录 `settings.json` 的 API Key 同级防护；不引入 keyring 依赖。
- access_token 过期（留 60s 余量）时用 refresh_token 静默续期；失败清会话。
- **不做本地 JWT 验签**：token 来自 HTTPS token 端点，真正的权限判断在服务端；本地二进制任何门控都可被 patch，目标只是让正常用户走正确路径，不做反破解对抗。
- 会话文件被手工删除 → 回到未登录；这是预期行为，不是漏洞。

## 5. 配置

client_id 编译期硬编码于 `src-tauri/src/auth.rs`（public client，无密钥，泄露无害）。
回调 scheme 在 `src-tauri/tauri.conf.json` → `plugins.deep-link.desktop.schemes` 声明。

## 6. 已知约束

- 自定义 scheme 只在 App **安装后**由系统注册。开发态 `cargo run` 可能收不到回调；可用 `open "unoswitchkit://callback/?code=...&state=..."` 手动验证分发，或先构建 `.app` 安装一次。
- 换包（ad-hoc 签名 cdhash 变化）不影响 scheme 注册，但 TCC 权限需按既有流程重置。
- README「默认不联网、不上报」需修订：登录/刷新时会访问 UNOAuth 与 userinfo 端点。
